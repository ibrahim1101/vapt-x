# Registered-email verification

Email verification is optional and disabled by default. Set `EMAIL_VERIFICATION_ENABLED=1` only when configuring delivery. It uses the TLS SMTP settings `RECOVERY_SMTP_HOST`, `RECOVERY_SMTP_PORT`, `RECOVERY_SMTP_MODE`, `RECOVERY_SMTP_FROM`, `RECOVERY_SMTP_USERNAME` and `RECOVERY_SMTP_PASSWORD`, independently of `ACCOUNT_RECOVERY_ENABLED`. SSL or STARTTLS and certificate verification are required. Enabled invalid configuration prevents startup. Credentials stay outside source control. No live mail provider has been enabled or validated during development.

Signed-in browser users can inspect their own status and request a link in organization settings. Recipients cannot be supplied or changed through this endpoint: delivery goes only to the requesting account's registered email. API tokens cannot manage account verification. Requests require the existing session, trusted Origin and CSRF checks, and have a ten-attempt budget per account per fifteen-minute window. Already-verified accounts do not send additional mail.

Links contain a random 256-bit token in the fragment, which the browser removes from the address bar. Opening a link displays a confirmation form; verification requires an explicit submission. The token hash, user/address/credential-epoch binding, expiry and use marker are stored. Tokens last 24 hours, are atomically one-use, and are checked for expiration during redemption independently of Mongo TTL cleanup. Expired/used links, changed credentials or registered addresses, disabled accounts and disabled verification configuration cannot confirm. Password-recovery tokens cannot be used for verification.

Confirmation may occur while signed out or signed in to another account. It applies only to the address and account bound to the token, never the currently signed-in account by inference. It requires the trusted browser Origin but no existing session or CSRF cookie. Confirmation records verified-address metadata and a private account event. It does not create or rotate sessions, disable MFA, change passwords, grant organization membership/roles, or introduce a new sign-in requirement. Email changes invalidate the displayed verified state unless the verified address matches the current address.

This feature records proof of registered-email control. Mandatory verification policies, invitations and OIDC remain separate work. Delivery shares the three process-local SMTP slots and bounded socket timeouts used by recovery. Failed delivery invalidates the issued token and returns a generic error without SMTP details. There is no durable mail queue or delivery retry guarantee. Test acceptance uses mocked mail only.
