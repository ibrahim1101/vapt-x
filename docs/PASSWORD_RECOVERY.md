# Password recovery

Recovery is disabled by default. It requires an operator-configured SMTP service and does not activate any mail delivery during synthetic acceptance. Email verification, invitations and OIDC are separate remaining work; recovery does not make an email verified.

Set `ACCOUNT_RECOVERY_ENABLED=1` only when configuring delivery. Supply `RECOVERY_SMTP_HOST`, `RECOVERY_SMTP_FROM`, `RECOVERY_SMTP_MODE` (`ssl` or `starttls`) and `RECOVERY_SMTP_PORT` (normally 465 or 587 respectively). Set both `RECOVERY_SMTP_USERNAME` and `RECOVERY_SMTP_PASSWORD` if the relay requires authentication. Keep credentials outside source control. TLS certificate verification is required; there is no plaintext fallback. Enabled invalid configuration prevents API startup. `FRONTEND_URL` determines reset-link destinations.

The sign-in screen offers recovery when configured. Requests receive the same accepted notice for eligible and unknown accounts; this is not a constant-time delivery guarantee. Requests have a database-enforced ten-attempt budget per normalized email hash per fifteen-minute window. Reset completion has a separate per-token attempt budget, and enabled MFA retains its existing atomic attempt/replay controls. Disabled accounts cannot request or complete a reset.

Links contain a random 256-bit token in the URL fragment, not query parameters. The client removes the fragment from the address bar and holds the token in memory while the form is open. Only a SHA-256 token hash, account/email/credential-epoch binding, use marker and expiry are stored. Tokens expire after fifteen minutes, are claimed atomically once, and become invalid when the account's credential epoch changes. Mongo TTL indexes clean up expired records; expiration is checked during every redemption and does not rely on TTL cleanup timing.

An enabled authenticator or unused MFA recovery code is required to finish. Resetting a password preserves MFA, changes the credential epoch, invalidates old sessions and API tokens across organizations, and records a metadata-only account event. It never automatically signs in the requester. Epoch checks also deny credentials minted by an old request already in flight. Cleanup of old credential rows is secondary to these checks.

Anonymous request/complete endpoints require the configured trusted browser Origin but do not require an existing session or CSRF cookie. API tokens cannot use account routes. Tokens, passwords and email content are not logged by this implementation. Delivery failures return the same accepted notice and invalidate that issued token. Delivery uses bounded SMTP socket timeouts and at most three process-local delivery slots; it has no durable mail queue or delivery retry guarantee. Operator mail-provider quotas, monitoring and production delivery acceptance remain necessary. No live provider has been validated or enabled as part of development.
