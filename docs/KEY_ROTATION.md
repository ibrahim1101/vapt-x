# Stored secret key rewrapping

The operator-only `backend/rewrap_secrets.py` command re-encrypts stored MFA secrets/pending enrollment, webhook configuration and OIDC PKCE verifiers to the first configured Fernet key. It is not a browser endpoint and does not generate, distribute or delete keys. It never rotates the underlying MFA secret, webhook signing secret or PKCE verifier. All plaintext, credential epochs, session bindings, enablement and original Fernet timestamps remain unchanged.

Use your normal secured operator environment with explicit `MONGO_URL`, `DB_NAME` and the selected encryption key ring. The script does not load `.env` files automatically. Do not put secrets in command arguments or commit them. Select `--purpose mfa`, `--purpose webhook`, or `--purpose oidc`; repeat `--purpose` for multiple independent rings. Every selected ring must be configured before any database work starts. Only the selected field families are read or updated.

1. Back up the database and retain its matching original encryption keys securely. This tool does not replace backup/restore acceptance.
2. Prepend the new key to the appropriate ring (`MFA_ENCRYPTION_KEYS`, `WEBHOOK_ENCRYPTION_KEYS`, `OIDC_ENCRYPTION_KEYS`), retain all old keys, and restart the supported single API worker with the updated ring. Verify decryption works. Coordinate a maintenance window for credential/provider operations to minimize conflicts.
3. From `backend`, run `python rewrap_secrets.py --purpose mfa` (and other selected purposes). The default is a dry run. It streams records in batches of 100 and prints counts only; no secrets, ciphertext, URIs, account names or record identifiers are printed.
4. Review `would_update`, `current`, `invalid`, `conflicts` and `remaining`. Add `--apply` only when the selected keys/database and backup are correct. Updates match the original ciphertext and change only that field, so a concurrent password/MFA/provider/secret change cannot be overwritten.
5. Rerun the dry run. Require `ok=true`, `remaining=0`, and zero invalid/conflict counts across all selected field families before considering old key removal. Retry conflicts; investigate invalid/unreadable rows while retaining the old keys. Exit code 2 means invalid records, conflicts, bad configuration or a database failure. A successful dry run exits 0 even when `remaining` shows work to apply.
6. Retain old keys until every process has the updated ring and in-flight operations have drained. Recheck after stopping old workers/writers; a concurrent process using an old primary key can create more old ciphertext after a scan. OIDC flows expire after ten minutes, so waiting for them to drain is an alternative to rewrapping them. Test recovery/restore with the retained keys before retiring any key.

The command is idempotent: ciphertext already decryptable by the first key is left unchanged. MultiFernet rotation preserves the original encryption timestamp, so it cannot extend a PKCE verifier's lifetime. Deleted/disabled webhook rows are included if they retain encrypted configuration. Pending MFA enrollment may need to be restarted if its conditional confirmation races a rewrap; active factor secrets do not change. An in-flight decrypt using an old ciphertext still needs its old key.

Operations stream without a whole-database transaction. Interruption or database failure can leave a partially completed rotation; keep all keys, rerun the dry run and resume. Successful compare-and-swap does not guarantee no new writes occurred after the scan. There is no automatic schedule, key escrow, release activation or recovery of missing keys. Tests apply the command only to synthetic records in uniquely named disposable Mongo databases.
