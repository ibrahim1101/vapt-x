# Optional linked OIDC sign-in

OIDC is disabled by default. It adds an alternative sign-in method for existing accounts explicitly linked by their owner. It never creates users, matches identities by email, changes registered-email proof, assigns roles, or trusts provider MFA as a substitute for local MFA. Local password sign-in remains available. Organization admission and disabled-account/credential-epoch checks still apply.

Configure one confidential web client using `OIDC_ENABLED=1`, `OIDC_ISSUER`, `OIDC_AUTHORIZATION_URL`, `OIDC_TOKEN_URL`, `OIDC_JWKS_URL`, `OIDC_CLIENT_ID`, `OIDC_CLIENT_SECRET` and `OIDC_ENCRYPTION_KEYS`. Generate Fernet keys as for MFA; the first key encrypts short-lived PKCE verifiers and all keys decrypt. Keep old keys for at least the ten-minute flow lifetime when rotating. Do not commit client credentials or keys.

Register exactly **FRONTEND_URL + `/api/auth/oidc/callback`** with the provider. Use the Nginx/proxied API origin for the browser callback; a separate API URL does not change this redirect. Configure provider endpoints explicitly: no dynamic discovery, arbitrary callback, dynamic registration or user-supplied provider is supported. The provider must support `response_type=code`, `scope=openid`, `client_secret_post`, PKCE S256 and ID tokens signed with RS256 (RSA >=2048 bits) or ES256 (P-256), with a `kid` selecting one signing key. Only public HTTPS port 443 endpoints are supported, including in local development. HTTP/private identity servers are intentionally unsupported.

From organization settings, enter the current password and an unused local authenticator/recovery code when MFA is enabled, then choose the identity account at the provider. The callback binds that issuer/subject to the current existing account only if its initiating session and credential epoch remain valid. A unique index prevents one provider identity from linking to multiple accounts. Successful linking increments the credential epoch, invalidates earlier sessions/API tokens and installs a replacement browser session.

At sign-in, choose **Sign in with linked identity**, authenticate with the provider and explicitly complete sign-in back in VAPT-X. The completion page shows the registered VAPT-X account and requires local MFA when enabled. A five-minute, HttpOnly browser challenge is claimed once before creating a session. A required email-proof policy still results in a limited unverified session. OIDC email claims are never used as proof or for account matching.

Removing a link requires the current password/local MFA, increments the credential epoch and invalidates previous credentials. Removal remains available if OIDC has been disabled. Signing out of VAPT-X revokes its local session; it does not sign out of the identity provider. Provider password changes, session logout or account disablement do not automatically revoke already-issued VAPT-X sessions; use VAPT-X session/account administration. Back-channel logout and provider lifecycle synchronization are not implemented.

Flows have a ten-minute TTL with hash-only state/browser correlation, encrypted PKCE verifier, nonce and configuration revision binding. Callback state is claimed before exchange; retries after failure must start a new flow. The completion page’s back action invalidates its browser-owned flow/challenge and clears correlation cookies; cancellation also remains usable when OIDC is disabled. An exchange already in progress may finish. A single browser correlation cookie means starting another flow in the same browser replaces the previous flow. ID token validation checks signature, issuer, audience/authorized party, nonce and time claims. No provider access/refresh/ID token or authorization code is persisted. Fixed token/key requests pin public DNS with the original TLS server identity/Host, reject redirects/proxies, limit response sizes, and have a total exchange deadline and three process-local slots. Anonymous start requests use a database attempt budget keyed to the API-observed client address; shared proxies/NAT can share that budget.

Built-in Nginx omits callback access logs and Uvicorn removes callback query parameters from its access records. Configure any additional proxy, APM or infrastructure logs to redact callback queries and client secrets. Application errors do not echo provider details. Account history records linking/sign-in/unlinking metadata without provider subjects or tokens.

Startup validates configuration and creates TTL/unique indexes without contacting the provider. Acceptance uses disposable Mongo, generated signing keys and mocked HTTPS/provider responses. A passing synthetic suite is not live provider compatibility or production release acceptance. Provider discovery, provisioning, forced SSO, multiple providers, service identities and provider-specific rollout remain separate work.

Protocol references: [OpenID Connect Core](https://openid.net/specs/openid-connect-core-1_0.html) and [OAuth security best current practice, RFC 9700](https://www.rfc-editor.org/rfc/rfc9700.html).
